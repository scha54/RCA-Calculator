# Twelve-Factor architecture assessment

## Application boundary and conclusion

The deployed application is a static browser client. Its server-side unit is an immutable directory of HTML, CSS, JavaScript and release metadata served by Vercel's CDN or the included read-only Node server. Calculations, spreadsheet generation and scenario editing run in the user's browser. There are no API servers, workers, database connections or shared server sessions.

The applicable Twelve-Factor requirements are implemented for this architecture. Do not introduce a database, application API or queue solely to make a static client resemble a server application. Browser-local persistence is an explicit product constraint: assessments are tied to a browser/origin, are not an account-backed store, and require portable JSON backups. Cross-device durability or multi-user collaboration would require a separately designed authenticated backing service.

## Additional production hardening

- `vercel.json` selects Vite, frozen installation including build-time dependencies and `dist/` output. Security headers enforce same-origin scripts/connections, prevent framing, disable plugins and unwanted device permissions, suppress referrers and content sniffing. Inline styles remain necessary for React/Recharts; inline scripts and eval are not allowed.
- Documents and release metadata revalidate; hashed assets are immutable for one year. Unknown assets on the portable server return 404 rather than HTML. No client-side pathname routes currently require an SPA rewrite.
- The portable server rejects traversal, hidden files, symlinks escaping `dist/`, invalid URLs and unsupported methods. It has request/header timeouts and logs no query data. It requires no package dependency at runtime (Node standard library only).
- The same production headers are exercised by browser tests, including charts and Excel generation without CSP violations. Error-boundary behavior and privacy-preserving diagnostics are also tested.
- User-selected JSON files are limited to 1 MiB before reading and parsing; this bounds accidental oversized-file work. Existing structurally invalid browser records are retained in original storage until the user explicitly replaces them.
- CI uploads the exact release directory, including its hidden Vite manifest, and runs release-integrity, lifecycle, browser, accessibility and bundle-budget gates. Publishing/deployment is intentionally separate from the test job.

## Dependency advisory disposition

At the time of this assessment `npm audit` reports no high/critical findings after the Vitest upgrade. It still reports two moderate package entries for one advisory: ExcelJS 4.4.0 → UUID 8, [GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq). ExcelJS's currently published release requests UUID 8; there is no supported upstream resolution in that dependency range.

The advisory concerns UUID v3/v5/v6 with a caller-supplied output buffer. ExcelJS's source uses only UUID v4 for conditional-formatting identifiers; the calculator does not call or expose the affected UUID APIs, does not import XLSX files and supplies no UUID buffers. The browser export is ExcelJS's prebuilt browser bundle; overriding a nested installed package would not replace an embedded vulnerable implementation and would misrepresent remediation. No such override or audit suppression is applied. This residual third-party advisory must remain visible and be revisited when upstream publishes a compatible fix, or before introducing features that expose the affected operations. CI continues to block any high/critical audit findings.

## Readiness limits

Repository checks demonstrate application and portable-server readiness for the documented single-user screening workflow. They do not demonstrate a live Vercel release, hosting access controls, alerts, DNS/TLS, traffic capacity, account persistence, external scientific assurance or organisational acceptance of the residual dependency risk. The operational runbook records the deployment checks and recovery procedure; report these separately from passing code checks.
